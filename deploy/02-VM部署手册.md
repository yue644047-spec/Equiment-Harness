# VM 部署手册（内网 · 不使用 Docker）

> 前置：已按 `03-配置填写清单.md` 准备好参数。全程约 **20-30 分钟**（含数据库编译）。
> 适用系统：**RHEL 8 / Rocky 8 / Alma 8 / openEuler 20.03+ / 麒麟 V10**，x86_64，**glibc ≥ 2.28**。

---

## 第 0 步：确认 VM 系统合格（5 分钟，**必须先做**）

在 VM 终端执行：

```bash
cat /etc/os-release | head -2
ldd --version | head -1
uname -m
nproc; free -h; df -h /opt /data 2>/dev/null
```

**判定标准**：

| 检查项 | 要求 | 不满足怎么办 |
| --- | --- | --- |
| glibc | **≥ 2.28** | CentOS 7（2.17）**不支持**，必须换系统 |
| 架构 | x86_64 | 本离线包不含 ARM64 产物 |
| 内存 | ≥ 8G（推荐 16G） | 降低 worker 数量 |
| 磁盘 | /opt ≥10G、数据盘 ≥50G | 调整 `DIFY_DATA_ROOT` |
| root 权限 | 需要 | 用 sudo |

> 也可以直接跑离线包里的探测脚本：`bash /opt/dify-bundle/vm-probe.sh`

---

## 第 1 步：把离线包放进 VM

U 盘挂载后：

```bash
mkdir -p /opt/dify-bundle
cp -a /mnt/usb/deploy-bundle/. /opt/dify-bundle/
cd /opt/dify-bundle
ls                    # 应看到 packs/ prebuilt/ vm/ config/ packages/ MANIFEST.txt
cat MANIFEST.txt      # 核对文件大小与校验值
```

**校验完整性**（可选但推荐）：

```bash
cd /opt/dify-bundle
sha256sum packs/*.tar.gz | head
# 与 MANIFEST.txt 中记录的前 16 位比对
```

---

## 第 2 步：填写配置

```bash
cd /opt/dify-bundle
cp config/dify.env.template config/dify.env
vi config/dify.env
```

按 `03-配置填写清单.md` 填 15 项。**填完务必先跑第 3 步的模型网关验证**，否则装完发现模型不通要返工。

---

## 第 3 步：验证模型网关（关键）

```bash
# 对话模型
curl -s http://10.0.0.20:8000/v1/models -H "Authorization: Bearer sk-xxx" | head -30

# Embedding —— 必须返回向量，否则知识库用不了
curl -s http://10.0.0.20:8000/v1/embeddings \
  -H "Authorization: Bearer sk-xxx" -H "Content-Type: application/json" \
  -d '{"model":"bge-m3","input":"测试"}' | head -c 200

# Rerank（可选）
curl -s http://10.0.0.20:8000/v1/rerank \
  -H "Authorization: Bearer sk-xxx" -H "Content-Type: application/json" \
  -d '{"model":"bge-reranker-v2-m3","query":"测试","documents":["a","b"]}' | head -c 200
```

三条都通再继续。

---

## 第 4 步：一键安装

```bash
cd /opt/dify-bundle
sudo bash vm/install.sh
```

安装脚本会依次完成（每步都有输出）：

| 步骤 | 内容 | 耗时 |
| --- | --- | --- |
| 1 | 环境检查（glibc、命令、端口） | 秒级 |
| 2 | 生成密钥、建 dify 用户与目录 | 秒级 |
| 3 | 部署便携 Python 3.12 + 依赖树（801 个包） | 1-2 分钟 |
| 4 | **编译安装 PostgreSQL 16.15 + pgvector** | 5-10 分钟 |
| 5 | **编译安装 Redis** | 1-2 分钟 |
| 6 | 写配置（Dify / Redis / 沙箱 / 插件守护进程） | 秒级 |
| 7 | 初始化数据库、建 dify 与 dify_plugin 库、启用 pgvector | 秒级 |
| 8 | 部署 API 源码、Web 前端、代码沙箱、插件守护进程 | 1 分钟 |
| 9 | 安装 systemd 单元并启动全部服务 | 1-2 分钟 |
| 10 | 配置 Nginx 并重载 | 秒级 |

> 若 PostgreSQL 编译失败，看 `/data/dify/logs/pg-configure.log` 与 `pg-make.log`。
> 若系统没有 gcc，脚本会自动改用离线包里的 zig 编译器。

安装成功时最后会打印访问地址和管理员密码。

---

## 第 5 步：自检

```bash
cd /opt/dify-bundle
sudo bash vm/verify.sh
```

期望输出：所有关键项 `[ OK ]`，最后一行显示"全部关键项通过，部署成功"。

重点关注第 7 项 **代码沙箱**：它会真实执行一段 Python 代码，返回 `1+1=2` 才算通。
这一项不通，02/03 两个工作流的代码节点就跑不了，评价闭环直接断掉。

---

## 第 6 步：初始化 Dify

1. 浏览器打开 `http://VM的IP`（若改了端口就加端口）
2. 首次访问设置管理员账号，密码用 `dify.env` 里的 `INIT_PASSWORD`
3. 按 `03-配置填写清单.md` 第 3 节：
   - 安装两个离线插件（DeepSeek + OpenAI-API-compatible）
   - 配置模型（注意 Embedding/Rerank 的 Base URL **不要带 /v1**）
   - 设置系统默认模型
   - 建知识库、上传 6 份装备资料
   - 导入三个 DSL 并绑定知识库

---

## 第 7 步：服务管理速查

```bash
# 查看全部服务状态
systemctl status postgresql-dify redis-dify dify-api dify-worker dify-worker-beat dify-web dify-plugin-daemon dify-sandbox

# 重启某个服务
sudo systemctl restart dify-api

# 看实时日志
sudo journalctl -u dify-api -f
tail -f /data/dify/logs/api.log

# 停 / 启全部
sudo systemctl stop dify-api dify-worker dify-worker-beat dify-web dify-plugin-daemon dify-sandbox redis-dify postgresql-dify
sudo systemctl start postgresql-dify redis-dify dify-api dify-worker dify-worker-beat dify-web dify-plugin-daemon dify-sandbox
```

---

## 第 8 步：开机会自动启动吗？

安装脚本已对这些服务执行了 `systemctl enable`，**开机自动启动**。
想关掉某个：`sudo systemctl disable --now dify-worker-beat`

---

## 升级与备份

**备份**（数据都在两个目录）：
```bash
sudo systemctl stop dify-api dify-worker dify-worker-beat
sudo tar -czf /backup/dify-data-$(date +%F).tar.gz /data/dify
sudo -u dify /opt/dify/pgsql/bin/pg_dump -h 127.0.0.1 -U dify dify > /backup/dify-db-$(date +%F).sql
sudo systemctl start dify-api dify-worker dify-worker-beat
```

**升级 Dify**：用新的 `packs/01-dify-source.tar.gz` 与 `03-api-deps.tar.gz` 覆盖后，
重启服务即可（`MIGRATION_ENABLED=true` 会自动跑数据库迁移）。
