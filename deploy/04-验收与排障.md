## 二、排障速查表

### 服务起不来

| 现象 | 排查 | 常见原因与解决 |
| --- | --- | --- |
| `dify-api` 反复重启 | `journalctl -u dify-api -n 100` | ① 数据库连不上：确认 `postgresql-dify` 在跑、密码与 `dify.env` 一致<br>② 迁移失败：手动 `sudo -u dify /opt/dify/python/bin/python3 -m flask upgrade-db`（在 `/opt/dify/api` 目录下） |
| `dify-web` 起不来 | `journalctl -u dify-web -n 50` | 多为 musl 加载器路径问题：确认 `/opt/dify/web/lib/ld-musl-x86_64.so.1` 存在；手工执行 `bash /opt/dify/web/start.sh` 看报错 |
| `dify-sandbox` 起不来 | `journalctl -u dify-sandbox -n 50` | ① glibc 过低：`start.sh` 应自动切到随包 glibc，确认 `/opt/dify/sandbox/glibc/` 有文件<br>② python_path 不存在：`/opt/dify/sandbox/python/bin/python3 -V` |
| `dify-plugin-daemon` 起不来 | `journalctl -u dify-plugin-daemon -n 100` | ① 未建插件库：`sudo -u dify /opt/dify/pgsql/bin/createdb -h 127.0.0.1 -U dify dify_plugin`<br>② Redis 密码错 |
| `postgresql-dify` 起不来 | `tail -50 /data/dify/logs/postgres.log` | 数据目录权限：`chown -R dify:dify /data/dify/postgres` |

### 安装阶段失败

| 现象 | 原因 | 解决 |
| --- | --- | --- |
| `glibc 2.17 过低` | VM 是 CentOS 7 | **换系统**（RHEL8/openEuler），无法绕过 |
| PostgreSQL `configure` 失败 | 无可用 C 编译器 | 确认 `packs/06-toolchain.tar.gz` 已解包，或安装 gcc |
| `pgvector 编译失败` | PG 头文件未装好 | 确认 `/opt/dify/pgsql/bin/pg_config` 存在 |
| 依赖树校验失败 | U 盘拷贝损坏 | 按 `MANIFEST.txt` 里的 SHA256 重新校验并重拷 |

### 功能不通

| 现象 | 定位 | 解决 |
| --- | --- | --- |
| 前端打开空白 / 一直转圈 | 浏览器 F12 看 Network | 检查 `DIFY_HOST` 是否是浏览器能访问的地址；`/console/api` 是否 502 |
| 上传文件失败 | nginx 日志 | `client_max_body_size` 已设 100M，超大文件需再调 |
| 知识库索引一直"排队中" | `journalctl -u dify-worker -f` | worker 没跑或队列名不对；确认 `CELERY_QUEUES` 与官方一致 |
| **索引直接报错** | worker 日志里的 embedding 报错 | 90% 是 Embedding 的 Base URL 多带了 `/v1`（见 03 文档 3.2.2） |
| 检索结果为空 | 知识库检索测试 | ① Embedding 维度填错 ② 文档没索引成功 ③ top_k 太小 |
| 代码节点报"沙箱不可用" | `curl -X POST http://127.0.0.1:8194/v1/sandbox/run ...` | 沙箱服务没跑，或 `CODE_EXECUTION_API_KEY` 与沙箱 `key` 不一致 |
| 插件安装报签名错误 | 插件页面提示 | 确认 `plugin-daemon.env` 中 `FORCE_VERIFYING_SIGNATURE=false` |
| 插件市场页面转圈 | 前端一直请求外网 | 确认 `MARKETPLACE_ENABLED=false`（离线必须关闭） |
| LLM 调用超时 | api 日志 | 网关不通 / 模型名不对；在 VM 上用 curl 直接验证网关 |
| 流式输出卡住不吐字 | nginx 配置 | 确认 `proxy_buffering off`（本包 nginx 配置已含） |

### 常用诊断命令

```bash
# 一键自检
sudo bash /opt/dify-bundle/vm/verify.sh

# 看某个服务最近日志
sudo journalctl -u dify-api -n 200 --no-pager

# 看 API 是否健康
curl -s http://127.0.0.1:5001/health

# 看插件守护进程
curl -s http://127.0.0.1:5002/health/check

# 手工测沙箱
curl -s -X POST http://127.0.0.1:8194/v1/sandbox/run \
  -H 'X-Api-Key: dify-sandbox' -H 'Content-Type: application/json' \
  -d '{"language":"python3","code":"print(2*3)","preload":"","enable_network":false}'

# 查数据库表
sudo -u dify /opt/dify/pgsql/bin/psql -h 127.0.0.1 -U dify -d dify -c '\dt' | head -30

# 查迁移版本
sudo -u dify /opt/dify/pgsql/bin/psql -h 127.0.0.1 -U dify -d dify -c 'SELECT * FROM alembic_version;'

# 磁盘占用
du -sh /opt/dify /data/dify
```

## 三、已知限制

| 限制 | 说明 | 影响 |
| --- | --- | --- |
| 不支持 CentOS 7 | 依赖里存在必须 glibc ≥ 2.27 的二进制包 | 必须换系统 |
| 不含 Agent v2 功能 | 未部署 `agent_backend` 服务 | Agent 节点不可用；普通 Chatflow/Workflow/知识库不受影响 |
| 不含 SSRF 代理 | 内网无外网可达 URL | 无 |
| 插件安装需手工搬运 | 内网无法访问插件市场 | 新增插件需在联网机下载 `.difypkg` 后拷贝安装 |
| 插件依赖需本地 wheel 仓库 | 插件运行时用 uv 建环境，离线需 `/opt/dify/pip-wheelhouse` 提供依赖 | 安装新插件前需把其依赖 wheel 放进该目录 |
| Web 前端为官方预构建产物 | 未在本机重新构建 | 无法直接改前端源码；如需改动需在联网机构建后替换 |
