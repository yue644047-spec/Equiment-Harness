# 配置填写清单（唯一需要你动手的地方）

> 本文件回答一件事：**为了让这套内网 Dify 跑起来，你需要填哪些值、填在哪里、去哪查。**
> 全流程只有 3 个填写位置，其余全部由脚本自动完成。

---

## 位置一：`deploy/config/dify.env`（部署前填，共 15 项）

**操作**：把 `deploy/config/dify.env.template` 复制成同目录下的 `dify.env`，按下表填写。

### 1.1 必填：访问地址

| # | 变量 | 填什么 | 示例 | 注意 |
| --- | --- | --- | --- | --- |
| 1 | `DIFY_HOST` | VM 的 IP 或内网域名 | `192.168.10.50` | **必须是使用者浏览器能访问到的地址**，不是 127.0.0.1 |
| 2 | `DIFY_HTTP_PORT` | 访问端口 | `80` | 被占用就换 `8080` |
| 3 | `DIFY_ENABLE_HTTPS` | `yes` / `no` | `no` | 内网无证书就填 no |

### 1.2 必填：路径与密码

| # | 变量 | 填什么 | 示例 | 注意 |
| --- | --- | --- | --- | --- |
| 4 | `DIFY_ROOT` | 程序安装目录 | `/opt/dify` | 需 ≥10G |
| 5 | `DIFY_DATA_ROOT` | 数据目录 | `/data/dify` | 建议独立挂盘，≥50G |
| 6 | `INIT_PASSWORD` | 控制台管理员初始密码 | `Dify@2026HYS` | ≥8 位含大小写与数字 |

> `SECRET_KEY` / `DB_PASSWORD` / `REDIS_PASSWORD` 三项**留空即可**，安装脚本会用 openssl 随机生成并写入。

### 1.3 ★ 最关键：内网大模型网关

> 这 7 项填错，Dify 能启动但**问答功能不可用**。填之前请先在 VM 上验证网关连通性（见第 4 节命令）。

| # | 变量 | 填什么 | 示例 | 去哪查 |
| --- | --- | --- | --- | --- |
| 7 | `MODEL_GATEWAY_BASE_URL` | OpenAI 兼容接口地址，**必须以 /v1 结尾** | `http://10.0.0.20:8000/v1` | 问模型服务管理员 |
| 8 | `MODEL_GATEWAY_API_KEY` | 网关密钥 | `sk-abc123...` | 同上；无鉴权填 `sk-noauth` |
| 9 | `MODEL_CHAT` | 对话模型名 | `deepseek-v3` | `curl $URL/models` 返回的 id 字段 |
| 10 | `MODEL_CHAT_ADVANCED` | 评分/标注用模型名 | `deepseek-v3` | 可与 9 相同 |
| 11 | `MODEL_EMBEDDING` | **Embedding 模型名** | `bge-m3` | **没有它知识库建不了索引** |
| 12 | `EMBEDDING_DIM` | 向量维度 | `1024` | 必须与 11 对应的模型一致 |
| 13 | `MODEL_RERANK` | Rerank 模型名 | `bge-reranker-v2-m3` | 网关没有就填 `none` |

### 1.4 容量（按上百人使用预设）

| # | 变量 | 填什么 | 示例 |
| --- | --- | --- | --- |
| 14 | `VM_CPU_CORES` | VM 的 CPU 核数 | `8` |
| 15 | `VM_MEM_GB` | VM 的内存 GB | `16` |

## 位置二：VM 上执行的验证命令（填之前先跑）

在 VM 终端里逐条执行，确认通过后再填 `dify.env`：

```bash
# ① 系统版本与 glibc —— 必须 >= 2.28（CentOS 7 是 2.17，不支持）
cat /etc/os-release | head -2
ldd --version | head -1

# ② 模型网关连通性 —— 必须能返回模型列表
curl -s http://10.0.0.20:8000/v1/models -H "Authorization: Bearer sk-你的key" | head -40

# ③ 确认 embedding 模型确实存在（在 ② 的输出里找，名字要一字不差）
curl -s http://10.0.0.20:8000/v1/models -H "Authorization: Bearer sk-你的key" | grep -i embed

# ④ 确认 embedding 接口真的能返回向量（这一步最关键，很多网关只挂名字不实现接口）
curl -s http://10.0.0.20:8000/v1/embeddings \
  -H "Authorization: Bearer sk-你的key" -H "Content-Type: application/json" \
  -d '{"model":"bge-m3","input":"液压系统额定压力是多少"}' | head -c 300

# ⑤ 磁盘与内存
df -h / /opt /data
free -h
```

> ④ 若返回 `{"data":[{"embedding":[...]}` 才算通过。返回 404 / 501 说明网关没实现 embedding，
> 那么知识库功能无法使用 —— 需要先让模型服务方补上，或换一个有 embedding 的网关。

## 位置三：Dify 控制台界面里填（部署完成后）

部署脚本跑完后，浏览器打开 `http://你的IP`，按下面顺序填。

### 3.1 设置管理员账号
首次访问会要求设置邮箱与密码（密码即 `dify.env` 里的 `INIT_PASSWORD`）。

### 3.2 安装模型供应商插件（离线方式）

因为内网无法访问插件市场，需要用离线包里的 `.difypkg` 文件安装。

**推荐安装两个插件（互补，缺一不可）：**

| 插件文件 | 作用 | 为什么需要 |
| --- | --- | --- |
| `deepseek-0.0.24.difypkg` | 提供对话模型 | ★ **它支持自定义 API Base URL**，所以现有三个 DSL 里的 LLM 节点（provider 为 `langgenius/deepseek/deepseek`）**一个字都不用改** |
| `openai_api_compatible-0.0.66.difypkg` | 提供 Embedding 与 Rerank | DeepSeek 插件不含 Embedding，而知识库必须要 Embedding 才能建索引 |

**安装步骤**：右上角头像 → **设置** → **模型供应商** → 右上角 **安装插件** → **通过本地文件安装** → 上传上述两个 `.difypkg`。

#### 3.2.1 配置 DeepSeek 插件（让现有 DSL 直接可用）

在该供应商右侧点 **添加模型 / 配置**，按下表填写：

| 字段 | 填什么 | 示例 |
| --- | --- | --- |
| API Key | 与 `dify.env` 的 `MODEL_GATEWAY_API_KEY` 一致 | `sk-abc123...` |
| **API Base URL** | 与 `MODEL_GATEWAY_BASE_URL` 一致 | `http://10.0.0.20:8000/v1` |

保存后点 **测试**，显示连接成功即可。此时 DSL 里的 `deepseek-flash` 等模型名若与网关不一致，
在**每个 LLM 节点的模型选择框**里改成网关实际提供的模型名（这一步在应用编排界面做，不用改 DSL 文件）。

#### 3.2.2 配置 OpenAI-API-compatible 插件（提供 Embedding / Rerank）

> ⚠️ **最容易踩的坑**：该插件对 **Embedding / Rerank / 语音** 这几类接口会**自动在地址后面追加 `/v1`**，
> 而对话模型不会。所以同一个网关，两类模型要填**不同的** Base URL：

| 模型类型 | 添加几个 | API Base URL 怎么填 | 模型名称 | 额外字段 |
| --- | --- | --- | --- | --- |
| LLM（可选，已被 DeepSeek 插件覆盖） | 1 | `http://网关/v1` | `MODEL_CHAT` | — |
| **Text Embedding** | 1 | `http://网关`（**不要带 /v1**） | `MODEL_EMBEDDING` | 向量维度 = `EMBEDDING_DIM` |
| **Rerank** | 1 | `http://网关`（**不要带 /v1**） | `MODEL_RERANK` | — |

举例：网关是 `http://10.0.0.20:8000/v1`，
- Embedding 的 Base URL 要填 `http://10.0.0.20:8000`，插件请求时补成 `http://10.0.0.20:8000/v1/embeddings`；
- 若照抄成 `http://10.0.0.20:8000/v1`，实际会请求 `http://10.0.0.20:8000/v1/v1/embeddings` → **404，知识库索引全部失败**。

每个模型添加后都要点 **测试**，显示连接成功才算通。

### 3.3 系统模型设置
**设置** → **模型供应商** → 页面下方 **系统模型设置**：
- 系统推理模型 → 选 `MODEL_CHAT`
- Embedding 模型 → 选 `MODEL_EMBEDDING`
- Rerank 模型 → 选 `MODEL_RERANK`（没有就留空）

### 3.4 导入三个 DSL 应用
**工作室** → **创建应用** → **从 DSL 文件导入**，依次导入：

| 顺序 | 文件 | 导入后必须做的修改 |
| --- | --- | --- |
| 1 | `dsl/01-多模态智能问答-Chatflow.yml` | 打开「知识检索」节点：把占位知识库 `00000000-0000-0000-0000-000000000000` 换成 3.5 步建好的知识库；`top_k` 设为 **6**；开启 Rerank |
| 2 | `dsl/02-满意度评价-Workflow.yml` | 把每个 LLM 节点的模型改为 `MODEL_CHAT_ADVANCED` |
| 3 | `dsl/03-多模态语料标注-Workflow.yml` | 同上 |

### 3.5 建知识库
**知识库** → **创建知识库** → 上传 `samples/` 下 6 份装备资料 → 分段设置选 **通用** → 索引方式选 **高质量（Embedding）** → 等待索引完成 → 记下知识库 ID 填回 3.4 的第 1 步。

> 上传前务必剔除作废版本段落：HYS-CZ-002 V3.0（滤芯周期旧值 300 工作小时）与
> HYS-GY-001 V2.0（额定压力旧值 14 MPa）不得进入知识库，版本判定以 HYS-ZL-005 V1.0 台账为准。

### 3.6 创建 API 密钥（给本地评测服务用）
分别进入三个应用 → **访问 API** → 创建密钥（`app-xxx`）；知识库 → **API** → 创建密钥（`dataset-xxx`）。
写入 Windows 侧 `%USERPROFILE%\.env`（**不要粘贴到聊天或提交到代码库**）：

```powershell
DIFY_BASE_URL=http://你的IP
DIFY_APP_API_KEY=app-xxx
DIFY_EVAL_API_KEY=app-xxx
DIFY_KB_API_KEY=dataset-xxx
```
