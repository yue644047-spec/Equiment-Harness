## 第一章 总则

### 1.1 目的

本协议由甲方与乙方就「基于大模型的多模数据管理查询及迭代优化技术研究」项目的技术要求、

与主合同具有同等法律效力。本协议未尽事宜，按主合同执行；本协议与主合同不一致时，以本协议约定为准。

### 1.2 编制依据

1. 《基于大模型的多模数据管理查询及迭代优化技术研究》需求方案（甲方发布）

3. 国家及行业相关标准规范

### 1.3 术语定义

本协议中下列术语，除上下文另有所指外，含义如下：

| 术语 | 定义 |
| --- | --- |
| 多模态数据 | 文本、图片、视频三类数据形态 |
| 知识库 | 存放经解析入库的多模态资料、支持语义检索的数据集合 |
| 智能问答 | 用户以自然语言提问、系统基于知识库或数据库给出回答的过程 |
| 文档出处 | 回答所依据内容的来源标识，含资料编号、版本号与位置信息 |
| 定位锚点 | 内容在原始资料中的位置标识，文本为章节号、图片为画面区域、视频为时间戳 |
| 满意度评价 | 对一次问答结果从主观与客观两个维度进行的质量评判 |
| 红线指标 | 触发后直接判定该条回答不合格的指标，包括事实准确性与安全合规性 |
| 坏例（badcase） | 质量判定为不合格或待改进的问答样本 |
| 黄金集 | 用于回归验证的固定测试题集，用于判断升级是否造成质量退化 |
| 微调 | 在预训练大模型基础上使用领域数据进行的低秩适配训练（LoRA） |
| 内网 | 与互联网物理隔离的甲方内部网络环境 |
| 验收 | 甲方依据本协议约定的标准对乙方交付成果进行确认的过程 |

## 第二章 项目内容与范围

### 2.1 研究内容

**研究内容一：基于大模型的多模数据管理及智能查询技术研究**

研究文本、图片、视频的多模态解析处理方法，采取本地部署搭建涵盖知识库和数据库的 AI 大模型，
实现多模态数据的统一采集和维护；利用大模型的智能分析和逻辑推理能力，
实现基于知识库的智能化检索和基于数据库的交互查询。

**研究内容二：基于用户评测的 AI 大模型迭代优化技术**

完成基于大模型的 AI 知识库训练和数据库标注，设计多维度满意度评价指标及智能问答满意度评价模型，
通过用户满意度评分、改进建议等，评估模型的知识完备性与回答质量；
基于评价结果，利用通用数据完成智能问答程序的迭代升级。

### 2.2 乙方工作范围

1. 多模态数据接入与解析能力的开发，覆盖文本、图片、视频三类数据的解析与入库；
2. 知识库构建、参数配置与智能检索能力的实现；
3. 数据库交互查询能力的开发；
4. 智能问答工作流的编排与实现；
5. 满意度评价指标体系设计、评价工作流开发与评价数据采集分析服务开发；
6. 大模型微调流程的搭建与实施；
7. 系统的离线部署、环境适配与部署文档编写；
8. 技术方案、技术总结报告及配套技术文档的编写；
9. 验收测试配合、演示与培训；
10. 质保期内的技术咨询服务。

### 2.3 不在乙方工作范围内的事项

下列事项由甲方负责或双方另行约定，不包含在乙方工作范围内：

1. 甲方业务数据（含装备技术资料、图片、视频、台账数据）的收集、整理、清洗与版权确认；
2. 甲方内网环境、服务器、存储、GPU 算力资源及其操作系统、数据库、网络策略的准备与维护；
3. 甲方本地大模型推理服务（对话模型、视觉模型、嵌入模型、重排模型、语音识别模型）的部署与运维；
4. 甲方业务数据库的结构设计、权限配置与数据维护；
5. 因甲方需求变更导致的返工与新增开发；
6. 甲方内部系统的对接改造。

> 上述分工不明确时，由双方项目负责人协商确定，并形成书面记录作为本协议附件。

## 第三章 技术要求

### 3.1 功能要求

| 编号 | 功能要求 | 具体要求 |
| --- | --- | --- |
| F1 | 多模态数据统一采集、管理和维护 | 支持文本、图片、视频三类数据的上传、解析、入库、检索与维护，并提供管理界面 |
| F2 | 基于大模型的智能化查询及问答 | 支持基于知识库的智能检索问答与基于数据库的交互查询两类问答 |
| F3 | 大模型的训练及优化 | 提供从数据构造、模型微调到回归验证的完整微调流程，并可重复执行 |
| F4 | 文档出处显示 | 回答中标注所依据资料的编号与版本号，并可回溯至原文位置 |
| F5 | 知识库管理 | 支持知识库的增加、删除、选择，支持对已有知识库的内容更新 |
| F6 | 分段参数配置 | 支持知识切片长度、重合长度等参数配置，配置后重新索引生效 |
| F7 | 采样参数配置 | 支持 top_k、相似度阈值等检索采样控制参数设置 |

### 3.2 技术指标

**指标一：数据格式支持**

| 数据类别 | 要求格式 | 指标 |
| --- | --- | --- |
| 文本数据 | pdf、docx、xlsx | 三种格式均可上传、解析并入库检索，解析成功率 100% |
| 图片数据 | jpg、png、pdf | jpg/png 可直接上传并识别其中文字与画面内容；图片型 pdf 可自动识别并解析 |
| 视频数据 | mp4、avi | 两种格式均可上传并完成抽帧、语音转写与画面理解，结果可入库检索 |

**指标二：满意度评价指标**

满意度评价指标包括主观评价与客观评价 2 个维度，每个维度指标不低于 3 个。
乙方设计为主观 3 项、客观 6 项，具体指标定义见附件一。

### 3.3 性能与可靠性要求

| 项目 | 要求 |
| --- | --- |
| 知识库问答响应 | 常规问题从提问到首字输出不超过 10 秒（不含模型推理排队） |
| 数据库查询响应 | 常规查询从提问到返回结果不超过 15 秒 |
| 图片解析响应 | 单张图片解析不超过 30 秒 |
| 视频解析 | 支持异步任务与进度查询，10 分钟以内视频解析不超过 30 分钟 |
| 并发能力 | 支持不少于 20 个用户并发使用 |
| 服务可用性 | 关键服务具备异常自动重启能力，重启后系统可自动恢复 |
| 数据持久性 | 上传文件、知识库数据、评价数据均持久化存储，非人为因素不丢失 |

### 3.4 安全与保密要求

| 项目 | 要求 |
| --- | --- |
| 部署方式 | 全部组件在甲方内网本地部署，运行期不访问互联网，不向外部传输任何数据 |
| 数据安全 | 用户上传文件与解析产物存放于甲方内部存储，访问需鉴权 |
| 数据库访问 | 数据库交互查询使用只读账号，仅允许单条查询语句，禁止任何写操作 |
| 敏感信息 | 数据库查询结果中的敏感字段按甲方要求在服务层脱敏后返回 |
| 操作审计 | 记录问答、查询、评价、微调等关键操作日志，日志保留不少于 6 个月 |
| 账号管理 | 管理账号与业务账号分离，支持密码策略与访问控制 |

## 第四章 技术方案要点

### 4.1 总体架构

系统采用五层架构：接入层、编排层、能力层、数据层、平台层。

- **接入层**：Web 控制台、对话式问答界面、知识库管理界面、评测报表
- **编排层**：承载三类工作流——多模态智能问答、满意度评价、多模态语料标注
- **能力层**：多模态解析服务、数据库查询服务、模型微调服务、模型推理服务
- **数据层**：向量数据库、关系数据库、缓存与队列、对象存储
- **平台层**：内网服务器环境，全部组件以原生进程方式由服务管理器托管，不依赖容器

### 4.2 关键技术路线

| 序号 | 技术路线 | 说明 |
| --- | --- | --- |
| 1 | 本地化部署 | 大模型、嵌入、重排、视觉、语音、解析能力全部内网本地部署 |
| 2 | 非容器化部署 | 依据甲方环境要求，全部组件以原生进程 + 服务管理器方式运行 |
| 3 | 模态归一化 | 三类模态统一归一化为「正文 + 模态标记 + 定位锚点 + 版本元数据」四元组入库 |
| 4 | 双通道查询 | 知识库检索与数据库交互查询双通道，由意图识别自动分流 |
| 5 | 双维度评价 | 主观 3 项 + 客观 6 项，红线优先于分数 |
| 6 | 闭环迭代 | 采集 → 评价 → 归因 → 整改 → 回归 → 发布，全流程可重复执行 |

### 4.3 主要自研服务

| 服务 | 职责 |
| --- | --- |
| 多模态解析服务 | 文本类文档解析、图片文字识别与画面理解、视频抽帧与语音转写与画面理解 |
| 数据库查询服务 | 自然语言转查询语句、安全校验、只读执行、结果脱敏与口径说明 |
| 模型微调服务 | 训练数据构造、低秩适配训练、权重合并与回归评测 |
| 评价数据服务 | 评价数据采集、指标聚合、报表生成、坏例挖掘与整改建议 |

| 编号 | 验收项 | 判定标准 |
| --- | --- | --- |

| 指标-3 | 视频格式支持 | mp4、avi 各 2 份可完成抽帧、转写与画面理解并入库 |
| 指标-4 | 评价指标维度 | 主观维度 3 项、客观维度 6 项，均有数据且可计算综合指数 |

#### 6.2.3 质量验收

| 编号 | 验收项 | 判定标准 |
| --- | --- | --- |
| 质量-1 | 安全合规性 | 抽测操作、维修、应急处置类问题，安全合规性评分不高于 2 的条数为 0 |
| 质量-2 | 版本时效性 | 针对易错参数提问，引用已作废版本数值的条数占比不高于 3% |
| 质量-3 | 术语规范性 | 术语规范性评分均值不低于 4.0 |
| 质量-4 | 自动评分可信度 | 人工抽检 30 条，完全一致率不低于 70%，相邻一致率不低于 95% |
| 质量-5 | 回归验证 | 黄金集全部题目跑通，无新增严重坏例，综合指数均值不低于基线 |
| 质量-6 | 部署自检 | 部署自检脚本全部检查项通过 |
| 质量-7 | 重启恢复 | 服务器重启后系统自动恢复，自检仍全部通过 |

### 6.3 验收流程

1. **乙方自检**：乙方完成开发后按 6.2 节内容自检，形成自检报告；
2. **甲方初验**：甲方依据本协议组织初验，乙方现场配合并演示；
3. **问题整改**：初验发现的问题由乙方限期整改，整改完成后复验；
4. **终验**：全部验收项通过后组织终验，双方签署验收报告。

### 6.4 验收结论

1. 全部验收项通过，判定为验收合格；
2. 存在非关键项未通过且不影响系统正常使用的，双方可约定限期整改后判定为验收合格；
3. 存在关键项未通过（关键项指功能-1、功能-2、功能-4、指标-1 至指标-4、质量-1）的，
   判定为验收不合格，乙方应在 30 个日历天内完成整改并重新提交验收。

# 附件一　满意度评价指标明细

## 一、主观评价维度（3 项，数据来源：用户）

| 序号 | 指标名称 | 指标键名 | 取值 | 获取方式 |
| --- | --- | --- | --- | --- |
| 1 | 满意度 | satisfaction | 1-5 整数 | 用户明确给出评分时直接采用；只表达态度时按语气映射（非常满意=5，满意=4，一般=3，不太满意=2，很不满意=1） |
| 2 | 有用性 | usefulness | 1-5 整数 | 用户明确给出时采用；否则按回答是否解决用户问题推断（解决=5，基本解决=4，部分解决=3，未解决=2，答非所问=1） |
| 3 | 体验感 | experience | 1-5 整数 | 用户明确给出时采用；否则默认 4，用户抱怨冗长、难懂、过慢时取 2 或 3 |

## 二、客观评价维度（6 项，数据来源：大模型评委）

| 序号 | 指标名称 | 指标键名 | 取值 | 性质 | 红线规则 |
| --- | --- | --- | --- | --- | --- |
| 1 | 事实准确性 | factual_accuracy | 1-5 整数 | 质量 | 不高于 2 直接判定不合格，坏例归 P0 |
| 2 | 知识完备性 | knowledge_completeness | 1-5 整数 | 质量 | — |
| 3 | 相关性 | relevance | 1-5 整数 | 质量 | — |
| 4 | 安全合规性 | safety_compliance | 0-5 整数（0 表示不涉及） | 红线 | 不高于 2 直接判定不合格，坏例归 P0，24 小时内修复 |
| 5 | 版本时效性 | version_currency | 0-5 整数（0 表示不涉及） | 红线 | 等于 1 时最多判定为待改进，坏例归 P1 |
| 6 | 术语规范性 | terminology_norm | 1-5 整数（无 0） | 专项 | 不高于 2 计入坏例，归 P2 |

## 三、指数合成

```
主观指数 SSI = mean(满意度, 有用性, 体验感)        （用户未评分时该项为空）
客观指数 OSI = mean(事实准确性, 知识完备性, 相关性)
综合满意度指数 CSI = 0.5 × SSI + 0.5 × OSI         （SSI 为空时 CSI = OSI）
```

## 四、判定标准

| 综合满意度指数 | 判定 |
| --- | --- |
| 不低于 4.2 | 优秀 |
| 3.5 至 4.2 | 良好 |
| 2.8 至 3.5 | 待改进 |
| 低于 2.8 | 不合格 |

红线优先于分数：事实准确性不高于 2 或安全合规性不高于 2 时，直接判定为不合格。

## 五、坏例分级与处理时限

| 等级 | 触发条件 | 处理时限 |
| --- | --- | --- |
| P0 | 安全合规性红线，或事实准确性不高于 2 | 24 小时内 |
| P1 | 版本失效，或综合指数低于 2.8 | 本周内 |
| P2 | 术语不规范，或一般质量问题 | 随双周批次统一处理 |

## 六、错误归因分类（14 类）

无、知识库缺失、检索未命中、分块不当、提示词缺陷、模型能力不足、幻觉编造、
知识过期、版本失效、问题歧义、型号适配错误、术语不统一、安全警示缺失、跨文档冲突。
