# 17 · 图数据库落地与国产化适配（Neo4j × 银河麒麟）

> 结论先行：**图数据库已经落地并在产品里跑通**（本机 Neo4j 2026.06.0 Community，独立实例 + 独立库）；
> **Neo4j 在银河麒麟（Kylin V10，x86_64 / ARM64）上可运行**，但有 4 个必须先确认的前提（JDK 版本、glibc 版本、
> 架构包、许可模式）。本文给出分层判断、已实测证据与国产替代切换方案。
> 决策登记：docs/16 ADR-D26。

## 1. 已落地的图数据库（本机实测，2026-09-27）

| 项 | 值 |
| --- | --- |
| 实例目录 | `D:\neo4j-equipment`（独立于同机另外 3 个 Neo4j 实例，互不影响） |
| 版本 / 版本类型 | Neo4j **2026.06.0 Community** |

这是 Windows 下的实际踩坑，已记录）。

### 1.1 产品里的读写链路（已实测通过）

```
切片 → 实体抽取(product/graph.py) → 本地 SQLite 图(离线兜底)
                                 └→ Neo4j(UNWIND 批量 MERGE)：Entity{dataset,id,name,category,weight} + RELATED{relation,weight}
```

| 能力 | 接口 | 实测结果 |
| --- | --- | --- |
| 图库状态 | `GET /api/graph/status` | 版本 `2026.06.0 community @ http://127.0.0.1:7485`，可达 |
| 构图并入库 | `POST /api/kb/datasets/{id}/graph/build` | 12 实体 / 18 关系写入 Neo4j |
| 实体检索（Cypher） | `GET /api/graph/entities?dataset_id=&q=` | 返回实体 + 权重 + 度数 |
| 邻居查询（Cypher） | `GET /api/graph/neighbours?dataset_id=&entity=` | 液压泵站 → 滤芯、系统维护… |
| 最短路径（Cypher） | `GET /api/graph/path?left=&right=` | `shortestPath` 可用（不连通时返回空） |
| 删库清理 | `DELETE /api/rf/datasets` | 图库残留 0（按 dataset 级联删除） |

## 2. 银河麒麟能不能跑 Neo4j：分层判断

Neo4j 是 **JVM 应用**（不是靠内核特性的原生程序），所以适配问题可以拆成四层，逐层都有明确判据：

| 层 | 判据 | 结论 |
| --- | --- | --- |
| ① JVM | Neo4j 5.x 需 **JDK 17**；2025+/2026 版需 **JDK 21** | 麒麟软件源自带 OpenJDK（**aarch64/x86_64 均有**）；本机实测 JDK 21 + Neo4j 2026.06.0 正常。**这是最关键也最容易满足的一层** |
| ② 系统调用/库 | Neo4j 本体依赖 glibc；Kylin V10 SP1 为 glibc 2.28 级（与 RHEL8/CentOS8 对齐） | 与 Neo4j 官方 Linux tarball 的目标一致，无特殊系统调用；公开部署案例（麒麟 + Neo4j 5.9.0）可佐证 |
| ③ 架构包 | 需要 **aarch64** 的 JDK 与 Neo4j tarball | Neo4j 官方提供 Linux ARM64 发行包；若某版本缺包，退路是"x86 服务器跑图库 + 麒麟 ARM 跑应用"（网络内网直连），或改用国产图库（§4） |
| ④ 服务化 | Kylin 用 systemd | 官方文档给出 systemd 单元写法，替换 Windows 服务即可；本产品只依赖 HTTP 7485，不绑定 Windows |

**必须实测确认的三件事（部署前 checklist）：**

1. `java -version` ≥ 17（建议 21），且 `java -XshowSettings:properties -version` 架构为 `aarch64`；
2. `ldd --version` ≥ 2.28；
3. 目标版本 Neo4j 是否存在 `neo4j-community-<ver>-linux-arm64.tar.gz`（无则按 §4 备选）。

> 说明：本文对"麒麟 + Neo4j"的判断依据是 **Neo4j 的运行形态（JVM + glibc）** 与公开部署记录（麒麟服务器 Neo4j 5.9.0 安装案例、
> "Neo4j 能否装在麒麟"的公开问答）；**尚未在真机麒麟上实测**——这是本项目"国产化适配"待办（与 docs/11 §7.4、docs/08 的 ARM64 真机验证项合并执行）。

## 3. 许可与合规（比技术更容易踩坑的一条）

| 项 | 事实 | 影响 |
| --- | --- | --- |
| Neo4j Community | **GPLv3** | 以"独立进程 + HTTP 接口"方式使用，产品自身代码不因此被传染；但**随交付物一起分发 Neo4j 二进制**时须履行 GPLv3 义务（附带许可证、提供对应源码获取方式） |
| Neo4j Enterprise | 商业许可 | 需要多库/RBAC/热备时使用，涉及采购 |
| 数据主权 | 全内网部署 | 满足离线要求；本产品只用 localhost HTTP 接口 |

**建议**：交付物内附 Neo4j 的 LICENSE 与版本说明（已在本机实例目录内保留 `LICENSE.txt`）；若甲方要求"全国产化组件清单"，
按 §4 切换到 NebulaGraph / HugeGraph。

## 4. 国产图数据库备选（我们的图后端已可插拔）

产品把图后端抽象为 `GRAPH_BACKEND=sqlite|neo4j`，切换只改配置，不改业务代码：

| 候选 | 许可 | 麒麟/ARM64 | 特点 | 切换代价 |
| --- | --- | --- | --- | --- |
| **Neo4j Community**（当前） | GPLv3 | JVM 应用，官方有 ARM64 包 | Cypher 生态最成熟、工具链最全 | — |
| NebulaGraph | Apache-2.0 | 国产，支持 ARM64 | 分布式、亿级图、nGQL | 需实现 `nGQL` 适配层（约 1 天） |
| HugeGraph（Apache） | Apache-2.0 | 国产，支持 ARM64 | 与 Gremlin 兼容、易与 Hadoop 生态整合 | 需实现 Gremlin 适配层 |
| 本地 SQLite 图（兜底） | 自有 | 无依赖 | 离线可用、零运维 | 无（已实现） |

> 现状：`sqlite` 后端**始终写入**（离线兜底与快速读图），Neo4j 为增强后端；即使图库不可达，门户仍可看图。

## 5. 风险与待办

| 风险 | 影响 | 处置 |
| --- | --- | --- |
| 麒麟 ARM64 真机未实测 | 交付前无法给出"已适配"结论 | 列入国产化验证清单，与 docs/08 ARM64 安装验证一起做（判据见 §2 checklist） |
| 客户不接受 GPLv3 组件 | 交付合规风险 | 切 NebulaGraph/HugeGraph（适配层已预留） |
| 单机内存有限（16GB 演示机） | JVM 堆与 Ollama 抢内存 | 已限制堆 2G / pagecache 512M；目标机按 32GB 显存方案配套 64GB 内存 |
| 演示机多实例端口冲突 | 启动失败 | 已用独立端口 7485/7695 + 独立服务名；部署文档固定该约定 |

## 6. 一句话交付口径

**图数据库这一环已经落地**：本机 Neo4j 2026.06.0（独立实例 + 独立库）承载实体与关系，产品侧构图即入库、
支持实体检索/邻居/最短路径等 Cypher 查询；**银河麒麟上可运行**的关键前提是 JDK 17/21 与 ARM64 发行包，
许可为 GPLv3（如需全国产化组件，可在不改业务代码的前提下切换到 NebulaGraph / HugeGraph）。
