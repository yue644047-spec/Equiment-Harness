## 1. 一句话说明

双击项目根目录的 **`启动演示系统.bat`**，会在本机拉起两个服务并自动打开浏览器：

| 服务 | 地址 | 对应设计报告 |
| --- | --- | --- |
| 检索契约层（kb_bridge） | http://127.0.0.1:9380/ | 3.5 知识库与检索契约层设计 |
| 治理看板（dashboard） | http://127.0.0.1:8848/ | 3.8 满意度评价 + 治理度量（docs/10） |

全部实现只依赖 **Python 标准库**，不需要 Dify、不需要 RAGFlow、不需要容器、不需要联网。

## 2. 演示内容（四个场景）

### 场景一：检索契约层与「版本硬过滤」（对应 3.5、4.7）

打开看板 **检索契约层** 页：

1. 输入问题「滤芯每 300 工作小时更换一次吗」，勾选 **版本过滤对比**，点检索；
2. 页面用 **Dify 外部知识库协议**（`POST /retrieval`，Bearer 鉴权）发起两次检索：
   - ① **硬过滤**结果：只剩现行有效版本条款（HYS-CZ-002 **V4.0**、HYS-WX-003 V2.0…）；
   - ② **放宽过滤**（演示开关）结果：**已作废的 V3.0 条款排在第一位**，内容是「每 300 工作小时」——正是设计要防住的失败模式；
3. 页面直接列出「被硬过滤挡下的片段」，可看到作废条款与现行条款的对照。

> 结论：**提示词是概率，元数据过滤是确定性**。演示版把这条红线放在了服务端强制注入，调用方（Dify）无法放宽。

### 场景二：资产库（对应 3.4、3.3 资产契约、指标 T3~T6）

打开 **资产库** 页：图片与视频的登记、检索与引用附件展示。

- 可检索维度：所属资料、所属章节、页码、图注标题、文件名、人工标签；
- 每个资产显示缩略图、图注、所属资料与版本、**挂载片段标识**、内容指纹；
- 演示资产 5 个（4 图 + 1 视频），均挂载在真实条款上；
- 页面明确标注：**只登记、只检索、不理解**（不 OCR、不抽帧、不转写）。

### 场景三：台账 / 履历查询（对应 3.7）

打开 **台账查询** 页，输入或点选示例：

| 问题 | 命中模板 |
| --- | --- |
| `EQ-1002 的履历` | 按装备编号查履历 |
| `HYS-1 的装备台账` | 按型号查装备台账 |
| `近三个月检修记录` | 查检修记录（含时间段解析） |
| `哪些装备保养要到期了` | 查保养到期（含已逾期） |
| `各状态各有多少台` | 按状态统计 |

结果页同时给出**命中的模板、实际执行的 SQL、参数与解释**，便于人工核对；安全约束为**只读连接**（`mode=ro` + `PRAGMA query_only`）+ **白名单模板** + 参数化绑定，不接受任意 SQL。

### 场景四：治理闭环（对应 3.8、docs/10）

**概览 / 缺陷整改单 / 归因明细 / 资料清单** 四页：

- 归因前置：15 条评价 → 文档缺陷 1 条 + 覆盖缺口 1 条 + 系统侧问题 2 条 + 未见异常 10 条；
- 文档质量记分卡：探针数、CSI、缺陷密度、DQI、Wilson 区间、样本充分性（样本不足不出结论）；
- 缺陷整改单：可筛选、可改状态（待整改 → 整改中 → 待验证 → 已关闭/已驳回）、可填责任单位与期限；
- 整改闭环率、未归因探针等指标直出。

## 6. 与正式交付的差距（如实说明）

| 项 | 演示版 | 正式交付 |
| --- | --- | --- |
| 检索后端 | 本地条款级 TF-IDF 索引（确定性、可解释、离线） | 变体 RAGFlow 架构（版式解析 + 向量/词项混合 + 重排） |
| 编排 | 看板内直接演示链路 | Dify Chatflow / Workflow（需 Dify 实例） |
| 解析 | 已治理的 Markdown 语料 | pdf / docx / xlsx 深度解析管线 |
| 资产 | 合成的演示图片与视频占位文件 | 真实装备图片与视频 + 审签流程 |
| 部署 | Windows 本机、标准库 | 国产 ARM64 + 国产 OS + 离线部署包 |
| 安全 | Bearer 鉴权、只读访问、目录穿越防护 | 完整密级控制、审计留痕、账号体系 |
| 微调 | 未含（仅黄金集回归防退化） | LoRA 微调 + 回归对比 + 模型切换 |

> 演示版的意义在于：**把设计中最容易"讲不清"的三件事变成可点击的现实**——版本硬过滤是否真的生效、资产在没有内容理解时能否被检索、台账查询如何做到既好用又不越权。

## 7. 排错

| 现象 | 处理 |
| --- | --- |
| 浏览器打不开 | 手动访问 http://127.0.0.1:8848/ ；端口被占用时用 `--port 其他端口` |
| 检索契约层显示"未连通" | 看板会**自动降级**为本地索引直查，功能不中断；如需服务模式，单独运行 `python kb_bridge\bridge_server.py --port 9380` |
| 中文显示乱码 | 脚本已设 `chcp 65001` 与 `PYTHONIOENCODING=utf-8`；若非 Windows 终端，先执行 `[Console]::OutputEncoding=[Text.UTF8Encoding]::new($false)` |
| 资产库为空 | 运行 `python tools\make_demo_assets.py --force` |
| 台账查询提示业务库不存在 | 运行 `python tools\make_demo_business_db.py --force` |
| 记分卡全部"样本不足" | 属预期：mock 数据每份资料探针不足 8 条；补齐覆盖探针集后即可出 DQI |
